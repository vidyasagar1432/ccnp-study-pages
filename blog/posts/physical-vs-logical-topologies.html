Physical vs Logical Topologies: Same Network, Two Views

The cable diagram and the forwarding diagram are not the same drawing. Confusing the two is one of the most common sources of bad designs, wrong troubleshooting, and missed exam questions.

Topology Design Switching Routing Fundamentals

1. Two Definitions That Must Stay Separate

Physical topology answers: where do the cables run, and what is plugged into what? It is the cable plant, the patch panels, the access points on the ceiling, and the circuits from the carrier.

Logical topology answers: how does traffic actually move? It is defined by forwarding behavior — MAC tables, VLANs, spanning tree state, IP subnets, routing adjacencies, overlays, and policy.

They are related but independent. The same physical layout can produce several different logical topologies, and a logical topology can be designed without changing a single cable. That is exactly why overlays, VLANs, and tunnels are powerful — and why they are easy to misdocument.

2. Why the Distinction Matters

  • Troubleshooting — a link that is physically up can be logically blocking (STP) or administratively unused (routing).
  • Design — redundancy is a physical property; resilience is a logical one. Two links are useless if the control protocol blocks one and never fails over.
  • Documentation — a cable map that omits VLANs and routing adjacencies cannot explain traffic flow.
  • Security — the physical path may bypass a firewall even though the logical subnet diagram suggests otherwise.
  • Cost — physical changes are slow and expensive; logical changes are fast and free, until they hit a hardware limit.

The link-count argument

For n nodes, a full mesh needs n(n−1)/2 links, a ring needs n, a star needs n (or n−1 if you count only spokes), and a hub-and-spoke needs n−1. This is why full mesh survives only where the number of nodes is small or the value of a direct path is unusually high.

4. The Classic Logical Topologies

Logical topologies use the same vocabulary but describe forwarding:

  • Logical bus — a shared broadcast domain. Modern switched Ethernet is physically a star but logically a bus per VLAN: a broadcast reaches every port in the VLAN.
  • Logical star — a central forwarding point. A switch is a logical star; a hub-and-spoke WAN is a logical star even when the underlying circuits form a mesh.
  • Logical ring — traffic follows a closed path. Token Ring is the historical example; SONET/SDH rings still use it; STP can also produce a logical tree from a physical ring.
  • Logical mesh — every node has a path to every other, though not necessarily a dedicated link. A routed network with full reachability is logically a mesh even if the physical topology is hierarchical.
  • Logical tree — a loop-free hierarchy of forwarding. This is what spanning tree deliberately creates on a physical mesh.
  • Overlay — a logical topology built on top of a different physical one: VXLAN over an IP fabric, DMVPN over internet links, SD-WAN over mixed underlays.

5. The Same Cables, Two Different Pictures

The clearest example is a triangle of three switches with redundant links. Physically it is a ring (or a partial mesh). Logically, spanning tree must block one link to prevent a loop, so traffic follows a tree.

Physical redundancy does not equal logical capacity. Spanning tree turns a physical loop into a logical tree — deliberately.

7. Wire vs Flow: How to Read Each View

Reading the physical view

  • Which ports are patched to which switch ports? Is the link copper, fiber, or radio?
  • Which links are cross-connects or carrier circuits?
  • Where does power come from — is PoE budgeted per switch?
  • What is the single point of failure if a device or cable is removed?

Reading the logical view

  • What is the VLAN and subnet of each endpoint?
  • Where is the default gateway, and is it first-hop redundant?
  • Which links are forwarding versus blocking (STP, LACP, routing)?
  • Which routing protocol advertises each prefix, and what is the backup path?
  • Where does policy apply — ACLs, firewall zones, VRFs, overlays?

8. Overlays: Deliberate Divergence

Overlay networks make the difference explicit. A physical underlay provides connectivity; a logical overlay provides the topology applications see.

  • VXLAN/EVPN — the underlay is a routed leaf-spine fabric, often with ECMP. The overlay is a set of Layer 2 segments identified by VNIs. VMs can move without changing subnets, even though the physical path changes entirely.
  • DMVPN — spokes build tunnels to a hub and learn each other's addresses, so the logical topology becomes a partial or full mesh over a hub-and-spoke underlay.
  • SD-WAN — the underlay is whatever circuits exist; the overlay selects paths per application based on policy and measured quality.
  • VPNs — a tunnel is a logical point-to-point link that may traverse dozens of physical hops and multiple providers.

The operational consequence: a traceroute shows the underlay, while the routing table shows the overlay. Both are correct, and neither alone explains the end-to-end path.

9. Design and Troubleshooting Guidance

  • Document both views. A physical diagram and a logical diagram answer different questions; keep both current.
  • Do not count blocked links as capacity. STP blocking, standby firewall pairs, and backup routes are resilience, not throughput.
  • Test failover, not just configuration. A redundant topology that never converges is only redundant on paper.
  • Watch the physical path of logical shortcuts. A tunnel or overlay can bypass the firewall or inspection point you assumed was inline.
  • Prefer routed links where loops are a risk. Layer 3 uses TTL and converges without blocking half the topology.
  • Mind asymmetry. Logical paths can differ per direction, which breaks stateful devices and confuses captures.
  • Check MTU across overlays. Each encapsulation layer reduces the usable payload; the logical path may be fine while large packets fail.

10. Exam Traps

  • "A star topology has no redundancy." The central device is a single point, but the spokes are independent; dual-homed stars exist.
  • "A ring is obsolete." SONET/SDH and metro fiber rings are still deployed, with protection switching measured in tens of milliseconds.
  • "Mesh is always better." Full mesh costs grow quadratically and add control-plane state; partial mesh is the usual answer.
  • "Logical topology equals VLAN layout." VLANs are one part of it; routing, STP state, overlays, and policy also define forwarding.
  • "A physically redundant triangle gives double bandwidth." Only if the control protocol uses both paths — STP does not, by default.
  • "Wireless has no physical topology." It has AP placement and RF cells; that is the physical layer of a wireless network.
  • "The cable diagram shows the path packets take." It shows possible paths, not the selected one.

11. Key Takeaways

  • Physical topology is the cable plant; logical topology is forwarding behavior.
  • The same physical network can present several logical topologies depending on VLANs, STP, routing, and overlays.
  • Physical redundancy is not logical capacity: blocked links, standby devices, and backup routes are for failure, not throughput.
  • Switched Ethernet is a physical star and a logical bus per VLAN; a triangle is physically a ring and logically a tree under STP.
  • Overlays deliberately separate the two views — underlay for connectivity, overlay for the topology applications see.
  • Design and troubleshoot with both drawings, and test the failure cases.
