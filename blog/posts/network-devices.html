Network Devices: Hub, Switch, Router, Firewall, and Access Point

Devices are best understood by the decision they make: repeat every bit, forward by MAC address, forward by IP prefix, enforce policy, or bridge wireless to wired. That decision determines everything else — domains, failure modes, and where the device belongs.

Switch Router Firewall Access Point Hub Fundamentals

1. One Question Explains Every Device

Ask: what does this box look at to decide where a frame goes? The answer maps directly to the OSI layer and tells you almost everything else.

  • A hub looks at nothing. It repeats bits out every other port.
  • A switch looks at the destination MAC address.
  • A router looks at the destination IP address.
  • A firewall looks at flow state and policy — addresses, ports, application, user.
  • An access point bridges 802.11 frames to 802.3 frames, usually by MAC address.

2. Where They Sit

A typical enterprise path: ISP → router → firewall → core → access → endpoint. Not every network needs every box, but the order reflects the decisions being made.

3. Hub — The Layer 1 Repeater

A hub is a multiport repeater. Bits arriving on one port are regenerated and sent out every other port, with no address inspection at all. That single design choice produces all of its properties:

  • One collision domain — every attached device competes for the same medium.
  • One bandwidth pool — a 100 Mbps hub shares 100 Mbps among all ports, not per port.
  • Half duplex — devices cannot send and receive simultaneously without colliding.
  • CSMA/CD required — carrier sense, collision detection, and backoff govern access.
  • No privacy — every frame is visible to every attached station.

Hubs are effectively extinct in production, but they remain conceptually important: they are the baseline against which switching is measured. If a question asks how many collision domains exist, a hub adds none — it merges everything attached to it into one.

4. Switch — Layer 2 Forwarding

A switch solves the hub's problems by learning where MAC addresses live and forwarding frames only where they need to go.

The four behaviors

  1. Learn — record the source MAC and the port it arrived on in the MAC address table (CAM table), with an idle timer.
  2. Flood — if the destination is unknown, broadcast, or multicast, send it out every port in the VLAN except the one it arrived on.
  3. Forward — if the destination is known and on another port, send it out that port only.
  4. Filter — if the destination is on the same port it arrived on, drop it.

What that changes

  • Collision domains per port — each port is its own domain, which is why full duplex works.
  • Dedicated bandwidth — a 1 Gbps port gives 1 Gbps to that station, in each direction.
  • VLANs — logical segmentation of the broadcast domain; a VLAN is one Layer 2 network even if it spans many switches.
  • Spanning tree — redundant Layer 2 paths must be blocked to prevent loops, because Ethernet headers have no TTL.
  • Store-and-forward vs cut-through — store-and-forward checks the FCS before forwarding; cut-through starts forwarding after the destination MAC, trading error checking for latency.

The MAC table is finite, and MAC learning is trust-based: anyone can claim any source MAC. That is why port security, DHCP snooping, and Dynamic ARP Inspection exist.

Layer 3 switches

A Layer 3 switch is a switch that also routes in hardware. It typically uses switched virtual interfaces (SVIs) as default gateways and forwards at ASIC speed. In modern campus design, the core is often a Layer 3 switch doing inter-VLAN routing, with routed links to the access layer.

5. Router — Layer 3 Forwarding

A router forwards packets between IP networks. It strips the incoming Layer 2 header, looks up the destination IP in its routing table, decrements the TTL, and builds a new Layer 2 header for the next hop.

Core functions

  • Longest prefix match — choose the most specific route, not merely a matching one.
  • Broadcast boundary — routers do not forward broadcasts, which contains broadcast storms.
  • Path selection — static routes, OSPF, EIGRP, BGP populate the routing table; the FIB/CEF makes forwarding fast.
  • TTL decrement — prevents loops at Layer 3, which Ethernet cannot do on its own.
  • Edge functions — NAT, DHCP relay, VPN termination, QoS marking, and often the first firewall policy.

Control plane vs data plane

The control plane runs routing protocols and builds the RIB. The data plane forwards each packet using the FIB. A router can be "up" with routing adjacencies formed while forwarding is broken — for example, when the FIB is not programmed or an ACL drops traffic in hardware. Troubleshooting must check both.

6. Firewall — Policy, Not Just Filtering

A firewall's defining behavior is to deny by default and permit only what policy allows. That is the opposite of a router, which forwards by default and blocks only where configured.

Generations and capabilities

Type Decision basis Limitations
Packet filter (stateless ACL) 5-tuple per packet, no memory Must permit return traffic explicitly; easy to misconfigure
Stateful inspection Connection table tracks TCP/UDP/ICMP flows Asymmetric routing breaks state; table exhaustion is a real failure
Application proxy Terminates and inspects the application protocol Performance cost; protocol support is finite
NGFW App-ID, URL category, user identity, IPS, TLS inspection Policy complexity, encrypted traffic blind spots, CPU cost

Deployment details that matter

  • Zones — inside, outside, DMZ. Policy is expressed between zones, not between individual hosts, in most designs.
  • Order matters — firewalls evaluate top-down; a broad permit above a specific deny silently disables the deny.
  • State and asymmetry — if the return path bypasses the firewall, the stateful check fails. This is the classic reason a firewall "randomly drops" traffic.
  • High availability — active/standby or active/active pairs; state synchronization is what makes failover transparent for established flows.
  • Transparent vs routed — a transparent (Layer 2) firewall can be inserted without readdressing; a routed firewall becomes a next hop.

7. Access Point — Bridging Wireless to Wired

An access point is a Layer 2 bridge between 802.11 and 802.3. Clients associate with a BSS identified by a BSSID (usually the radio's MAC), and the SSID is the network name users see. Authentication happens before the client can pass traffic.

What an AP does

  • Beacons and probes — advertises the SSID and capabilities; clients discover and select.
  • Association and authentication — open, WPA2/WPA3-Personal, or 802.1X enterprise.
  • Encryption — per-client keys (CCMP/GCMP), so over-the-air traffic is protected.
  • Bridging — converts frames between the wireless and wired formats, preserving the client's MAC in typical deployments.
  • Roaming support — coordinated handoff between APs (802.11k/v/r help; the client ultimately decides).

Autonomous vs controller-based

An AP is not a router. A home "wireless router" is several devices in one box: router, switch, access point, DHCP server, and often firewall and NAT. In enterprise designs those functions are separated deliberately.

9. How They Fail

Device Characteristic failure First things to check
Hub Collisions, shared bandwidth collapse Collision counters, duplex settings
Switch Loop/broadcast storm, MAC table exhaustion, VLAN mismatch show mac address-table, STP state, interface errors
Router Missing route, ARP failure, one-way forwarding show ip route, show ip arp, CEF, ACLs
Firewall Policy shadowing, state table exhaustion, asymmetry Connection table, policy hit counts, routing symmetry
Access point Co-channel interference, weak coverage, roaming stickiness Channel utilization, client RSSI/SNR, retry rates

10. Design Notes

  • Switch where you can, route where you must. Layer 2 is simple and fast; Layer 3 contains failure domains and scales better across sites.
  • Keep the firewall on the path it inspects. Inserting it asymmetrically creates state mismatches that look like random drops.
  • Give each VLAN one gateway. Multiple Layer 3 gateways on one VLAN invite proxy-ARP and inconsistent forwarding.
  • Plan PoE before APs. 802.3af (15.4 W), at (30 W), and bt (60–90 W) budgets add up quickly on a 24-port switch.
  • Design wireless for capacity, not just coverage. A strong signal with a congested channel is still a bad experience.
  • Redundancy needs a control protocol. STP, FHRP, and routing protocols decide which path is active; without them, redundancy becomes a loop.

11. Exam Traps

  • "A hub is a Layer 2 device." No — it is pure Layer 1; it does not read MAC addresses.
  • "A switch breaks broadcast domains." Not by itself. Only VLANs (or a router) create separate broadcast domains.
  • "Routers create collision domains." Switches create one per port. A router's interfaces are separate collision domains too, but that is not why we deploy them.
  • "A firewall is just an ACL." A stateless ACL is a packet filter; a firewall tracks state and usually enforces zone policy.
  • "The AP routes wireless traffic." It bridges. Routing happens at the gateway.
  • "A Layer 3 switch cannot route." It routes in hardware; that is the point.
  • "A home wireless router is just an AP." It combines router, switch, AP, DHCP, NAT, and often firewall functions.

12. Key Takeaways

  • Classify a device by the decision it makes: repeat, MAC-forward, IP-forward, enforce policy, or bridge a medium.
  • Hubs merge collision domains; switches divide them per port; VLANs divide broadcast domains.
  • Routers separate subnets and contain broadcasts; Layer 3 switches do the same at ASIC speed inside a campus.
  • Firewalls deny by default and add state; asymmetry and policy order are the usual culprits when they misbehave.
  • Access points are Layer 2 bridges with radio physics attached — capacity and interference matter as much as configuration.
  • Real designs combine devices and separate functions deliberately; "wireless router" is a bundle, not an architecture.
