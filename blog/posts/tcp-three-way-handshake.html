TCP Three-Way Handshake: Explained in Depth

A detailed look at TCP connection establishment, SYN/ACK/FIN/RST flags, sequence and acknowledgment numbers, the TCP state machine, and practical troubleshooting tips.

TCP Transport Handshake Networking Fundamentals

1. What is TCP?

Transmission Control Protocol (TCP) is a connection-oriented, reliable transport layer protocol defined in RFC 793. Unlike UDP, TCP ensures data is delivered in order, without loss, and without duplication. Before any application data is exchanged, TCP must establish a logical connection between the client and server using the three-way handshake.

2. Why the Three-Way Handshake?

The three-way handshake serves three critical purposes:

  • Synchronization - Both ends agree on initial sequence numbers (ISN) to track bytes.
  • Connection establishment - Confirms both hosts are alive and willing to communicate.
  • Parameter negotiation - Allows negotiation of TCP options like MSS (Maximum Segment Size), Window Scale, and Selective Acknowledgments.

3. TCP Flags Explained

TCP uses control flags in the header to manage connections. The most important for the handshake are:

Flag Name Purpose
SYN Synchronize Used to initiate a connection and synchronize sequence numbers.
ACK Acknowledgment Indicates the receiver has received data and is acknowledging it.
FIN Finish Used to gracefully terminate a connection.
RST Reset Aborts a connection immediately (used when something is wrong).
PSH Push Requests immediate delivery of data to the application.
URG Urgent Indicates data should be processed urgently.

4. The Three-Way Handshake Process

Let's assume a client (e.g., 192.168.1.10) wants to connect to a server (e.g., 10.0.0.5) on TCP port 443 (HTTPS).

Step 1: SYN (Client → Server)

The client initiates the connection by sending a TCP segment with the SYN flag set.

  • Source Port: Ephemeral port (e.g., 49152)
  • Destination Port: 443
  • Flags: SYN
  • Sequence Number (SEQ): Client's Initial Sequence Number (ISN), e.g., 1000
  • Window Size: Indicates buffer space available

The client transitions to SYN_SENT state.

Step 2: SYN-ACK (Server → Client)

If the server accepts the connection, it responds with a segment containing both SYN and ACK flags.

  • Flags: SYN + ACK
  • Sequence Number (SEQ): Server's ISN, e.g., 5000
  • Acknowledgment Number (ACK): Client ISN + 1 = 1001 (acknowledging the client's SYN)

The server transitions to SYN_RECEIVED state.

Step 3: ACK (Client → Server)

The client acknowledges the server's SYN by sending an ACK segment.

  • Flags: ACK (SYN may be cleared)
  • Sequence Number (SEQ): 1001 (next sequence number)
  • Acknowledgment Number (ACK): Server ISN + 1 = 5001

The client transitions to ESTABLISHED, and upon receiving this ACK, the server also transitions to ESTABLISHED. The connection is now fully established and data transfer can begin.

7. TCP Connection Termination (Four-Way Handshake)

While not the main focus, it's important to know how TCP closes gracefully. This uses FIN and ACK in a four-way exchange:

  1. FIN - One side sends FIN to indicate no more data to send
  2. ACK - Other side acknowledges the FIN
  3. FIN - Other side sends its own FIN
  4. ACK - First side acknowledges, and both enter TIME_WAIT/CLOSED states

In some cases (abort), a RST is sent instead for immediate termination.

8. TCP State Machine (Key States)

State Description
CLOSED No connection exists
LISTEN Server waiting for incoming connection requests
SYN_SENT Client has sent SYN and is waiting for SYN-ACK
SYN_RECEIVED Server received SYN, sent SYN-ACK, waiting for ACK
ESTABLISHED Connection is open, data transfer can occur
TIME_WAIT Waits to ensure all packets are cleared before closing (typically 2MSL)
CLOSE_WAIT Received FIN, waiting to close its side
LAST_ACK Sent FIN, waiting for final ACK
FIN_WAIT_1/2 States during active close process

9. Sequence and Acknowledgment Numbers in Depth

TCP is byte-stream oriented, not packet-oriented. Sequence numbers track the first byte in the segment.

  • Initial Sequence Number (ISN) - Randomly generated to prevent spoofing and ensure uniqueness across connections.
  • SEQ increment - After sending N bytes, the next SEQ = current SEQ + N (with SYN/FIN counting as 1 byte each).
  • ACK number - Tells the sender "I have received up to ACK-1, send me ACK next". This is cumulative acknowledgment.

Example: Client sends SEQ=1000, 100 bytes of data → Next SEQ will be 1100. Server responds with ACK=1100, meaning it expects byte 1100 next.

10. Troubleshooting the TCP Handshake

When a connection fails, understanding the handshake helps pinpoint the issue.

Symptom Likely Cause Investigation
No response to SYN Server down, IP unreachable, or ACL blocking Check routing with ping/traceroute, verify ACLs
SYN sent, RST received Port closed, service not listening, or firewall rejecting Verify service is running on server, check firewall rules
SYN-SYN/ACK works, no ACK from client Asymmetric routing, NAT issues, or client firewall Capture traffic on both sides, check routing tables
Connection times out Stateful firewall dropping return traffic Check connection tables, ensure return path exists

Useful Commands

# Check TCP connections and states
netstat -an | grep <port>
ss -tlnp
ss -tan

# Test connectivity to a specific TCP port
telnet <server_ip> <port>
nc -vz <server_ip> <port>

# Packet capture (Wireshark/tcpdump)
tcpdump -i eth0 host <server_ip> and port <port> -nn

11. Key Takeaways

  • Three steps: SYN → SYN-ACK → ACK establishes the connection.
  • Reliability starts here: ISNs are synchronized to ensure ordered, reliable delivery.
  • Flags matter: Only SYN, ACK are used in the pure handshake (RST can abort).
  • Stateful protocol: Both ends track connection state throughout the session.
  • Half-open connections: SYN_RECV state can be exploited (SYN floods) - mitigated by SYN cookies.
  • Not needed for UDP: UDP is connectionless, so no handshake occurs.
