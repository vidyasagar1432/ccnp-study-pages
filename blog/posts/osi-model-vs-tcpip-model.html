OSI Model vs TCP/IP Model: In-Depth Comparison

A comprehensive breakdown of the OSI 7-layer model and the TCP/IP model, including their layers, protocols, encapsulation, data flow, key differences, and CCNP exam-relevant concepts.

OSI TCP/IP Networking Fundamentals

1. Introduction

Network communication is complex. To make it manageable, networking models break this process down into smaller, standardized layers. The two most important models you'll encounter are the OSI (Open Systems Interconnection) model and the TCP/IP (Transmission Control Protocol/Internet Protocol) model.

The OSI model is a theoretical, vendor-neutral reference model developed by the ISO. The TCP/IP model is the practical model that powers the modern internet and is what real-world networks actually use today.

2. The OSI Model (7 Layers)

The OSI model consists of 7 layers, numbered from Layer 7 (closest to the user) to Layer 1 (closest to the physical medium). A common mnemonic to remember from top to bottom is "All People Seem To Need Data Processing", and from bottom to top "Please Do Not Throw Sausage Pizza Away".

Layer # Name PDU Function Devices/Examples Protocols
7 Application Data Provides network services directly to end-user applications. Handles user interfaces, authentication, and resource availability. End-user apps HTTP/HTTPS, DNS, SMTP, POP3, IMAP, FTP, SNMP, Telnet, SSH
6 Presentation Data Translates, encrypts, compresses, and formats data. Ensures data is readable by the receiving application. Gateways SSL/TLS, JPEG, GIF, ASCII, EBCDIC, MPEG
5 Session Data Establishes, manages, and terminates sessions between applications. Handles dialog control and synchronization. Gateways NetBIOS, RPC, PPTP, NFS
4 Transport Segment (TCP) / Datagram (UDP) Provides reliable or unreliable end-to-end delivery. Handles segmentation, flow control, error recovery, and port numbers. Firewalls TCP, UDP
3 Network Packet Logical addressing (IP), routing between different networks, path determination, and fragmentation. Routers, Layer 3 switches IP, ICMP, OSPF, EIGRP, RIP, BGP, IPsec, ARP (associated)
2 Data Link Frame Physical addressing (MAC), framing, error detection, access to the media, and flow control on local segments. Switches, Bridges, NICs Ethernet, IEEE 802.11 (Wi-Fi), PPP, HDLC, Frame Relay, STP
1 Physical Bits Defines electrical, mechanical, and procedural specifications. Transmits raw bits over the physical medium. Hubs, Cables, Repeaters, Transceivers Ethernet cables, Fiber, RS-232, DSL, IEEE 802.3 physical standards

3. The TCP/IP Model (4 Layers)

The TCP/IP model is a protocol suite model originally developed by DARPA. It's more condensed than OSI and focuses on the protocols actually used on the internet. It has 4 layers:

Layer # Name PDU Function Protocols
4 Application Data Combines OSI Layers 5, 6, and 7. Handles application services, data representation, and session management. HTTP, HTTPS, DNS, SMTP, FTP, DHCP, Telnet, SSH, SNMP
3 Transport Segment (TCP) / Datagram (UDP) Same as OSI Layer 4. Provides reliable (TCP) or connectionless (UDP) communication between hosts. TCP, UDP
2 Internet Packet Equivalent to OSI Layer 3. Handles logical addressing, routing, and internetwork communication. IP (IPv4/IPv6), ICMP, IGMP, ARP, IPsec
1 Network Access Frame / Bits Combines OSI Layers 1 and 2. Handles physical transmission and access to the local network media. Ethernet, Wi-Fi (802.11), PPP, MAC, Frame formats

4. Encapsulation and Data Flow

When data travels across a network, each layer adds its own header (and sometimes trailer) in a process called encapsulation. On the receiving end, decapsulation occurs as each layer removes its corresponding header.

Encapsulation Process (Sending Host)

Layer Action PDU Name
Application/Presentation/Session (OSI) or Application (TCP/IP) Data created by the application Data
Transport Adds TCP/UDP header (source/destination ports, sequence numbers) Segment/Datagram
Network/Internet Adds IP header (source/destination IP addresses) Packet
Data Link/Network Access Adds Layer 2 header/trailer (source/destination MAC, FCS) Frame
Physical Converts frame to electrical/optical/radio signals Bits

Example: Accessing a Website (HTTP/HTTPS)

Let's walk through what happens when you type https://example.com into your browser:

  1. Application Layer - Browser uses HTTP(S) to request the webpage. DNS resolves the domain name to an IP address.
  2. Transport Layer - TCP establishes a 3-way handshake (SYN, SYN-ACK, ACK) and segments the data. Source/destination ports are used (e.g., ephemeral source port to 443).
  3. Internet/Network Layer - IP adds source and destination IP addresses. Routing determines the path to the remote server.
  4. Network Access/Data Link Layer - Ethernet adds source/destination MAC addresses. ARP is used if the next-hop MAC isn't known.
  5. Physical Layer - The frame is converted to bits and transmitted across the medium.
  6. Decapsulation - Each hop and ultimately the destination reverses this process, stripping headers until the HTTP response reaches the browser.

5. OSI vs TCP/IP: Side-by-Side Comparison

Feature OSI Model TCP/IP Model
Origin Developed by ISO in 1984 as a theoretical reference model Developed by DARPA in the 1970s for ARPANET, evolved into the internet model
Number of Layers 7 Layers (Application, Presentation, Session, Transport, Network, Data Link, Physical) 4 Layers (Application, Transport, Internet, Network Access)
Approach Vertical, generic, and protocol-independent. Designed before protocols existed. Horizontal, practical, and protocol-driven. Built around TCP, IP, and UDP.
Usage Primarily used for learning, troubleshooting, and conceptual understanding Used in all real-world networks and the internet
Transport Layer Guarantees reliable delivery (connection-oriented) and is strictly defined TCP provides reliability, UDP is connectionless. Both are core to the model
Addressing Uses different addressing at different layers (e.g., MAC at L2, IP at L3, ports at L4) Similar addressing, but layers are more consolidated
Model Type Reference model (guideline) Protocol suite model (implementation-based)
Strictness Very strict boundaries between layers More flexible, layers often overlap in practice

7. Troubleshooting with the Models

The OSI model is especially powerful for structured troubleshooting. A popular approach is to start from the bottom up or top down depending on the issue.

Layer Common Issues Troubleshooting Tools/Commands
Physical (1) Cable damage, bad connectors, loose cables, interface down show interfaces, cable tester, TDR
Data Link (2) MAC errors, duplex mismatch, VLAN misconfiguration, STP issues show mac address-table, show interfaces, show spanning-tree
Network (3) IP misconfiguration, routing issues, ACL blocks ping, traceroute, show ip route
Transport (4) Port blocking, TCP handshake failures, firewall rules telnet <ip> <port>, nc, packet captures
Session/Presentation/Application (5-7) DNS failures, SSL issues, app misconfiguration nslookup/dig, browser dev tools, curl, logs

8. Key Takeaways for CCNP

  • Know both models - OSI is for concepts/troubleshooting, TCP/IP is for real-world operation.
  • Memorize PDUs - Bits (L1), Frame (L2), Packet (L3), Segment/Datagram (L4), Data (L5-7).
  • Understand encapsulation - Be able to trace headers as data moves down the stack.
  • Focus on transport - TCP is connection-oriented and reliable, UDP is connectionless and faster.
  • Use OSI for troubleshooting - The layered approach helps isolate issues efficiently.
  • Remember consolidation - TCP/IP combines OSI's upper layers into Application and lower layers into Network Access.

9. Quick Comparison Summary

Question Answer
Which model is used on the internet? TCP/IP Model
Which model has exactly 7 layers? OSI Model
Which layer handles IP addressing? OSI Layer 3 / TCP/IP Internet Layer
Which layer handles MAC addressing? OSI Layer 2 / TCP/IP Network Access Layer
Which model is more theoretical? OSI Model
Where do HTTP, DNS, and FTP operate? OSI Layer 7 / TCP/IP Application Layer
