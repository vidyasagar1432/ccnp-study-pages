Encapsulation and De-encapsulation: How Data Gets Wrapped and Unwrapped

Every message is put inside envelopes, one per layer, and taken out again at the other end. Understanding that wrapping explains headers, MTU failures, NAT, and tunnels.

Encapsulation Headers PDU MTU Fundamentals

1. The Core Idea

Encapsulation is the process of a layer taking the data handed to it by the layer above, adding its own header (and sometimes a trailer), and passing the result down. De-encapsulation is the reverse: each layer strips its own header, verifies it, and hands the payload up.

Think of nested envelopes. The application writes a letter. TLS puts it in a sealed envelope. TCP writes delivery details on the outside. IP adds the destination address. Ethernet adds the local courier instructions for this one leg of the trip. At the destination, each envelope is opened by the layer that sealed it.

Three consequences follow, and they explain almost everything in this article:

  • Overhead is unavoidable. Every layer's header consumes bytes from the link's maximum frame size.
  • Each layer only reads its own header. A switch never inspects the TCP port; a router never inspects the HTTP request.
  • Headers are per-scope. The Ethernet header is valid for one link only; the IP header is valid end to end.

2. Wrapping, Layer by Layer

Left: each layer adds one header to the payload it receives. Right: a router replaces the Layer 2 header and decrements TTL, leaving the end-to-end payload intact.

3. What Each Header Is For

Layer Header (typical size) Key fields Decision it enables
L2 — Ethernet 14 bytes (+4 FCS trailer, +4 per VLAN tag) Destination MAC, source MAC, EtherType, 802.1Q tag Which local port or station receives this frame
L3 — IP 20 bytes (IPv4), 40 bytes (IPv6) Source/destination IP, TTL/hop limit, protocol, fragmentation fields (IPv4) Which path and which host receives this packet
L4 — TCP/UDP 20 bytes TCP, 8 bytes UDP Source/destination port, sequence and acknowledgment numbers, flags, window, checksum Which process receives the payload, and how reliably
L6 — TLS 5-byte record header, plus authentication tag Content type, version, length, nonce/tag How to decrypt and verify the application data

Each header exists so that exactly one device or process can make exactly one decision. That is the whole design: local decisions use local information.

4. What Changes at Each Hop

Encapsulation is not static. As a packet crosses the network, different parts of it are rewritten:

Device Reads up to Rewrites Leaves alone
Hub / repeater Layer 1 Nothing — regenerates signals Everything
Switch Layer 2 Nothing in the frame (it forwards it) MACs, IP, TCP, payload
Router Layer 3 Source and destination MAC, TTL, FCS; checksum updated IP addresses (without NAT), ports, payload
NAT device Layer 3–4 IP addresses, port numbers, IP and TCP/UDP checksums Application payload (unless an ALG rewrites it)
Firewall Layer 3–7 Nothing by default; may rewrite or block Forwarded traffic
Proxy / load balancer Layer 7 Terminates the connection and creates a new one Nothing — it is a new session end to end
Tunnel endpoint Layer 3+ Adds an outer header around the entire original packet The inner packet, encrypted or not

This table is why "the router changes the MAC address" is true while "the router changes the IP address" is false by default. It is also why a capture taken on each side of a NAT device shows different addresses for the same conversation.

5. De-encapsulation: Who Opens Which Envelope

At the receiver, de-encapsulation is driven by explicit demultiplexing keys:

  1. NIC and Layer 2 — verify the destination MAC and the FCS. If the frame is for this station (or broadcast/multicast), strip the Ethernet header and read the EtherType: 0x0800 = IPv4, 0x86DD = IPv6, 0x0806 = ARP.
  2. Layer 3 — verify the destination IP, check the header checksum (IPv4), decrement TTL only if forwarding, then read the protocol number: 6 = TCP, 17 = UDP, 1 = ICMP, 47 = GRE, 50 = ESP.
  3. Layer 4 — look up the destination port in the socket table, verify the TCP/UDP checksum, and hand the payload to the owning process.
  4. Application — decrypt TLS if present, then parse HTTP, DNS, or whatever the application expects.

Intermediate routers stop at step 2 or 3. Only the final host goes all the way up. That is why a router can forward traffic it cannot read: it never opens the inner envelopes.

Note on checksums: the FCS protects one link only and is regenerated at every hop. The IP checksum covers only the IP header (IPv4). The TCP/UDP checksum covers the header, the payload, and a pseudo-header containing the IP addresses and protocol — which is exactly why NAT must recalculate it.

6. Overhead, MTU, and Why Small Packets Are Expensive

A 1500-byte Ethernet MTU is not 1500 bytes of payload. Ethernet takes 14 bytes plus a 4-byte FCS, IPv4 takes 20, TCP takes 20 — leaving 1460 bytes for data.

Application payload Headers (Eth + IP + TCP) Total on the wire Efficiency
1460 bytes58 bytes1518 bytes96.2%
512 bytes58 bytes570 bytes89.8%
100 bytes58 bytes158 bytes63.3%
40 bytes (VoIP)58 bytes98 bytes40.8%

Two extra rules matter in practice:

  • Minimum frame size. Ethernet requires 64 bytes including FCS. A small payload is padded to reach it, so very small packets cost more than the table suggests.
  • Fragmentation. If a packet exceeds the MTU of a link and the DF bit is clear, IPv4 can fragment it. IPv6 routers never fragment; the source must size packets correctly. See Segmentation and Reassembly for the full mechanics.

7. Tunnels: Encapsulation Inside Encapsulation

A tunnel takes a complete packet and puts it inside another packet. The inner headers remain intact; the outer headers belong to the transport network. This is how VPNs, VXLAN, and MPLS-style overlays work.

Encapsulation Typical added bytes Effect on usable MTU
802.1Q VLAN tag41496
PPPoE81492
GRE (outer IPv4)241476
IPsec ESP tunnel mode50–73~1427–1450
VXLAN (outer Eth + IP + UDP + VXLAN)501450
MPLS label stack (2 labels)81492

The failure mode is a classic: pings and small requests work, large transfers stall. The path MTU is smaller than the sender assumes, the DF bit prevents fragmentation, and the ICMP "fragmentation needed" message is filtered out by a firewall — a PMTUD black hole. Fixes include clamping TCP MSS on the tunnel interface (ip tcp adjust-mss 1400 on Cisco), lowering the interface MTU, or allowing ICMP type 3 code 4 (and ICMPv6 "packet too big") through the policy.

9. Practical Checks

# Can this path carry a full 1500-byte packet without fragmenting?
ping -M do -s 1472 203.0.113.10        # 1472 + 8 ICMP + 20 IP = 1500

# Where does the path MTU shrink?
tracepath 203.0.113.10
mtr --report-wide 203.0.113.10

# See each layer's headers in a capture
tcpdump -i eth0 -nn -vv -c 20 'tcp port 443'
# In Wireshark: Frame -> Ethernet II -> Internet Protocol -> TCP -> TLS

# Cisco: verify and adjust
show interfaces GigabitEthernet0/1 | include MTU
show ip interface GigabitEthernet0/1
interface Tunnel0
 ip tcp adjust-mss 1400

10. Exam Traps

  • "Encapsulation means encryption." No. Encryption is a payload transformation that may be wrapped by encapsulation (as IPsec does), but the two are independent.
  • "Routers change the source and destination IP addresses." Only NAT does that. Routers rewrite the Layer 2 header and decrement TTL.
  • "Switches de-encapsulate to Layer 3 to forward." A Layer 2 switch reads the Ethernet header only. A Layer 3 switch does route, but that is a separate function.
  • "The FCS travels end to end." It is recalculated on every link and discarded by the receiving NIC.
  • "TCP's checksum covers the IP header." It covers a pseudo-header derived from IP addresses and protocol, not the whole IP header.
  • "Routers fragment IPv6 packets." They do not; only the source fragments IPv6.
  • "De-encapsulation happens only at the destination host." Every device de-encapsulates up to the layer it needs — a switch to Layer 2, a router to Layer 3 — then re-encapsulates.

11. Key Takeaways

  • Encapsulation adds a header per layer going down; de-encapsulation removes one per layer going up.
  • Each layer's header enables one decision: local delivery (L2), path selection (L3), process delivery (L4), interpretation (L5–7).
  • Layer 2 headers and FCS are per-hop; IP addresses, ports, and payload are end to end.
  • Routers rewrite Layer 2 and decrement TTL; NAT additionally rewrites addresses and ports and must fix checksums.
  • Overhead is real: 58 bytes per packet on a normal Ethernet/IPv4/TCP path, leaving 1460 of 1500 bytes.
  • Tunnels stack encapsulation and shrink the usable MTU — which is why MSS clamping and PMTUD exist.
  • Most "large transfers fail" tickets are encapsulation problems, not application problems.
