The 4 Layers of TCP/IP: The Model the Internet Actually Runs On

OSI is a reference. TCP/IP is the implementation. Its four layers — Application, Transport, Internet, and Network Access — describe the protocols that carry every packet you send.

TCP/IP OSI Protocols Encapsulation Fundamentals

1. Why Four Layers Instead of Seven

The OSI model was written first, as a design. TCP/IP was written second, as working code — and the code shipped. When the protocols were later documented in RFC 1122, they were described in four layers, not seven.

The reduction is not laziness; it reflects what the protocols actually do:

  • Session and presentation were folded into the application. In TCP/IP there is no separate session or encryption layer. Applications handle their own sessions (cookies, tokens), and TLS sits between transport and application as a library, not a layer of the stack.
  • Link and physical were folded together. TCP/IP is deliberately agnostic about media. Ethernet, Wi-Fi, fiber, PPP, and cellular all sit in one "Network Access" layer because IP only needs them to carry a frame.
  • The model describes protocols, not abstract functions. OSI asks "what should a network do?" TCP/IP asks "what do these protocols actually do?"

2. The Four Layers

The four TCP/IP layers next to the seven OSI layers they replace, with the protocols that actually run at each one.

Application layer (OSI 5, 6, 7)

Everything the user or program interacts with: web requests, name resolution, mail, file transfer, remote shells, and the encryption that wraps them. In TCP/IP, this layer also absorbs the session and presentation responsibilities — the application decides how a session starts and ends, and TLS handles encoding and encryption.

  • Protocols: HTTP/HTTPS, DNS, SMTP, IMAP, POP3, FTP, SSH, Telnet, SNMP, DHCP, NTP, SIP.
  • Not a layer: TLS/SSL. It is a library that sits between transport and application, which is why it does not map cleanly to any single OSI layer.

Transport layer (OSI 4)

End-to-end delivery between processes, identified by port numbers. This is where reliability, ordering, flow control, and congestion control live — or deliberately do not.

  • TCP — connection-oriented, reliable, ordered, with a three-way handshake and retransmission.
  • UDP — connectionless, best-effort, minimal overhead; used by DNS, DHCP, VoIP, and QUIC.
  • SCTP — message-oriented with multiple streams; common in telecom signaling.
  • QUIC — runs over UDP and builds reliability plus TLS 1.3 inside user space; it blurs the transport/application boundary but is standardized as a transport protocol.

Internet layer (OSI 3)

Logical addressing, path selection, and best-effort delivery across independent networks. IP does not promise delivery; it promises an address and a next hop.

  • IPv4 / IPv6 — addressing, fragmentation, TTL/hop limit.
  • ICMP — errors and diagnostics (ping, traceroute); protocol number 1.
  • Routing protocols — OSPF (89), EIGRP (88), and BGP (TCP 179). They are routing applications, but they exist to build the Internet layer's forwarding table.

Network Access layer (OSI 1, 2)

The media-dependent layer. IP hands it a packet; it hands back a frame on the wire, fiber, or radio. Everything that changes when you move from Ethernet to Wi-Fi to a cellular link lives here.

  • Technologies: Ethernet (802.3), Wi-Fi (802.11), PPP, DSL, DOCSIS, cellular (LTE/5G), fiber (SONET, GPON).
  • Functions: framing, MAC addressing, media access (CSMA/CD, CSMA/CA), link-layer error detection (FCS), VLAN tagging.
  • ARP — maps an IP address to a MAC address. It is usually placed here because it does not cross routers, even though it carries an IP address.

4. Encapsulation in Practice

A single HTTPS request from a laptop shows the whole model at work. Sizes assume IPv4 and TCP with no options and a standard 1500-byte MTU:

Application   HTTP GET /index.html HTTP/1.1 ...
              + TLS record (encrypts the HTTP bytes)

Transport     [ TCP header 20 B ][ TLS + HTTP payload ]        = segment
              src port 51422, dst port 443, seq/ack, flags

Internet      [ IP header 20 B ][ TCP segment ]                 = packet
              src 10.0.0.25, dst 93.184.216.34, TTL 64, proto 6

Network       [ Eth header 14 B ][ IP packet ][ FCS 4 B ]       = frame
Access        dst MAC = default gateway, src MAC = laptop NIC,
              EtherType 0x0800 = IPv4

Physical      0 1 1 0 1 0 0 1 ... on the wire

Overhead adds up: 14 + 4 bytes of Ethernet, 20 bytes of IPv4, and 20 bytes of TCP leave 1460 bytes of payload — the TCP MSS. That is why an MTU mismatch or a tunnel that adds encapsulation breaks large transfers while small pings still work.

Decapsulation and demultiplexing

At the receiver, each layer uses a field to decide who gets the payload next:

  1. Frame — check the destination MAC and FCS, then read the EtherType (0x0800 = IPv4, 0x86DD = IPv6, 0x0806 = ARP).
  2. Packet — check the destination IP, decrement TTL, then read the protocol number (6 = TCP, 17 = UDP, 1 = ICMP, 47 = GRE, 50 = ESP).
  3. Segment — check the destination port and hand the payload to the matching socket or service.
  4. Application — parse the bytes according to HTTP, DNS, TLS, or whatever the port implies.

5. Where the Model Gets Fuzzy

The four layers are a useful map, not a law of physics. Several protocols deliberately straddle boundaries:

Protocol Usual placement Why it is ambiguous
ARPNetwork AccessCarries an IP address but never leaves the local link; often called "Layer 2.5"
ICMPInternetEncapsulated directly in IP (protocol 1), no ports, but used by application tools
BGPInternet (routing)Runs over TCP port 179, so it also looks like an application
TLSBetween Transport and ApplicationEncrypts application data but runs over TCP; OSI calls it presentation
QUICTransport (over UDP)Bundles reliability, TLS 1.3, and stream multiplexing in one protocol
MPLSBetween Link and InternetForwards on labels, not IP; often called "Layer 2.5"
GRE / IPsec tunnelsInternetEncapsulate an entire IP packet inside another IP packet, effectively stacking layers

If an exam asks where something belongs, use the conventional answer: ARP and MAC in Network Access, IP and ICMP in Internet, TCP and UDP in Transport, everything user-facing in Application. Then know the exceptions, because that is what the tricky questions test.

6. Troubleshooting with Four Layers

The model's practical value is narrowing the search. Each layer has a distinct failure signature and a distinct first test.

Layer Typical symptom First checks
Network AccessNo link, no ARP entry, wrong VLANLink lights, show interfaces, show mac address-table, ARP cache, duplex/speed
InternetCan reach local subnet but not remoteping gateway and remote IP, traceroute, show ip route, ACLs
TransportPing works but the service does notTest the port (nc -vz, telnet), firewall policy, NAT translations
ApplicationConnection succeeds but the app failsDNS resolution, TLS certificate, HTTP status codes, application logs

A useful habit: never troubleshoot two layers at once. Confirm the link, then reachability, then the port, then the application — in that order. Skipping ahead wastes time on problems the lower layer has already caused.

7. Exam Traps

  • "TCP/IP has seven layers." It has four. The seven-layer model is OSI; the five-layer hybrid is a teaching compromise.
  • "The TCP/IP application layer equals OSI layer 7." It covers OSI layers 5, 6, and 7.
  • "TCP/IP has a session layer." No; session handling is part of the application or of TCP itself.
  • "ARP is a Layer 3 protocol because it deals with IP addresses." It is conventionally placed in the link layer; it does not route.
  • "TLS is a transport protocol." It runs over TCP and encrypts application data; treat it as sitting between transport and application.
  • "The Internet layer guarantees delivery." IP is best-effort. Reliability is TCP's job, and even then only end to end.
  • "BGP is an application protocol." It uses TCP, but its purpose is building the Internet layer's routing table.

8. Key Takeaways

  • The TCP/IP model has four layers: Application, Transport, Internet, and Network Access.
  • It exists because it describes the protocols that actually run, rather than an abstract design.
  • Application absorbs OSI 5–7; Network Access absorbs OSI 1–2.
  • Each layer adds its own header: TCP adds ports, IP adds addresses, Ethernet adds MAC addresses and an FCS.
  • Demultiplexing uses EtherType, then the IP protocol number, then the port number.
  • Some protocols straddle layers — ARP, ICMP, TLS, QUIC, MPLS — and knowing why is what separates memorization from understanding.
